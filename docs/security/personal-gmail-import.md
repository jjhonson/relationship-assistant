# Person-first Gmail import (private alpha)

This is a bounded, explicitly activated single-owner feature. It is not automatic sync, a public OAuth application or mailbox discovery. Keep the private Codespace port and the Mac loopback tunnel; never make the port public.

The personal connection uses the existing read-only OAuth client with a separately authorized exact redirect URI: http://localhost:3001/api/gmail/callback. The existing fictional/development port 3000 callback and cookies remain separate. No Gmail request occurs on relationship-page load. Register the personal callback in the existing Google OAuth client only after owner approval. Do not paste credentials into chat or Git.

Activation requires the protected personal runtime, RA_PERSONAL_GMAIL_ENABLED=yes, and RA_PERSONAL_GMAIL_REDIRECT_URI=http://localhost:3001/api/gmail/callback in the private personal configuration. Live body processing additionally requires RA_PERSONAL_GMAIL_MODEL_APPROVED=yes and an explicitly named existing model configuration (OPENAI_RELATIONSHIP_MODEL). Keep both flags off until the owner has approved live access, Google restricted-scope/policy and provider processing requirements have been reviewed, and the permitted model cost has been disclosed. No actual OAuth configuration or API usage is authorized by this document.

From a relationship, select Import from Gmail. Connecting grants read-only account access, not permission for automatic scanning. Optionally search 24 headers for candidate addresses; confirm identity and authorize a bounded 40-header lookup. The server holds an exact one-use review for at most five selected messages; review expires after ten minutes and is bound to the person, connection and personal dataset. Separate affirmative permissions for body retrieval and OpenAI processing/charges precede every import. Only structured observations and provider provenance persist; the provider request sets store:false (not a guarantee of zero provider retention). No attachment endpoints, whole-thread reads, sending or background polling. A session can be refreshed only by an explicit action and expires after seven days. Disconnect clears local cookies and pending review handles; revoke the Google OAuth grant independently. An already-started import may finish; disconnect is not cancellation of an in-flight provider request.

Limits: direct apparent one-to-one mail, plain-text MIME only, bounded recent-first sample, no calendar artifacts, no alias inference, no complete history guarantee. Same-day possible manual overlap and cross-person conflicts are held out, not resolved. Conflicting non-provider observations remain deferred, not projected as current facts. No commitment reconciliation or headshots yet. An incomplete or ambiguous outcome must be checked before retrying; provider-key dedupe prevents a second memory for the exact same imported message. Browser acceptance, Google policy/consent configuration, actual cookie/redirect behavior and live model extraction still need separate review. No extra paid service or public deployment.

## Live-use gate, reviewed November 28, 2026

Google lists CRM and email productivity as eligible use cases and provides personal/testing exceptions to OAuth verification. These exceptions do not waive Limited Use or secure handling obligations. Before any live body/AI import, verify the Google test-user and client configuration, the model/API pricing and data-sharing settings (training opt-in off), and a usable path for reviewing and deleting Gmail-derived memory, including backup implications. Do not claim this draft meets public-app verification, privacy-policy publication or security-assessment requirements. Do not turn on the live flags until the owner explicitly approves. In-product notice must distinguish store:false from zero retention: standard API abuse-monitoring logs may retain content up to 30 days, subject to provider exceptions and account controls. The person page includes source-aware review and removal of selected imported messages from the active dataset, with explicit confirmation and stale-review protection. Removing source-backed memory does not delete Gmail mail, user-authored records, external provider copies/logs or historical encrypted backups; those require separate handling. Independently supported facts remain; a new explicit import may bring the information back. Validate the removal path before live activation. No actual deletion is authorized by this document.

## Multiple accounts

The first alpha supports one active read-only Gmail session at a time. A user may authorize another account after disconnecting and reconnecting, subject to Google OAuth test-user settings; both can contribute to the same relationship. Each source retains its mailbox-specific key and origin. This does not deduplicate copies of the same underlying email across different mailboxes. Defer simultaneous account connections, owner-address alias handling and cross-mailbox Message-ID/content-based deduplication until the first integration is accepted. Never assume access to another mailbox from the first account's authorization.
